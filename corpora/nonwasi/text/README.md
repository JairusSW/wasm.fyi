# Text, query, archive, and public-key pure-core replacements

These are **new contracts**, not ABI-identical builds of the old CLI programs.
The old IDs are used only to select a replacement in `scripts/nonwasi-text.mjs`.
Every returned manifest has a new ID and an explicit semantic mapping.

| Old CLI | New pure-core contract | Retained substantive work |
|---|---|---|
| coreutils-sort | rusttext-sort | stable byte-lexicographic sorting of 4,096 complete lines |
| coreutils-base64 | base64-rfc4648 | RFC 4648 standard and URL-safe encoding and decoding of 32,771 bytes |
| coreutils-wc | unicode-wordcount | line, word, byte, Unicode scalar, and extended grapheme counts |
| ripgrep-source | regex-source-scan | four regex compilations and complete source scanning, offsets, and matches |
| json2csv-people | serde-json2csv | JSON parsing and CSV serialization of 256 records with quoting/newlines |
| jq-json-transform | jaq-json-query | actual jq-language parsing, compilation and evaluation: map/select, sort, group, reduce |
| tree-list | zip-directory-extract | ZIP central-directory enumeration and CRC-checked extraction of 64 entries |
| age-keygen-public | x25519-public | 64 deterministic X25519 public-key derivations |

No filesystem, CLI, clock, entropy, syscall shim, unresolved symbol, or host
import is present. Rust's actual allocator manages invocation-local allocations;
the previous output buffer is freed when replaced. Inputs are regenerated by
the deterministic source recipe and embedded at compile time.

Build with Rust **1.90.0** and target `wasm32-unknown-unknown`. Cargo.lock pins
registry package versions and source checksums. The helper accepts `NONWASI_CARGO`,
`NONWASI_CARGO_HOME`, and `NONWASI_RUSTUP_HOME` for an isolated official toolchain.
It uses `cargo build --locked --release`, no default application feature, and
exactly one workload feature. No emulation or WASI target is used.

Each invocation hashes every output byte with FNV-1a-64. Before accepting a build,
the helper independently computes expected bytes in Node.js and checks both hash
and all exported output bytes on four calls to one instance. References use
Buffer sorting/Base64, Intl.Segmenter, JavaScript regex/JSON/CSV algorithms,
an independently generated ZIP directory/CRC, and OpenSSL-backed X25519 through
Node's crypto implementation. Exported output_ptr/output_len enable diagnostic
full-byte verification; benchmark is the measured zero-argument export.

The manifest records complete output SHA-256 and length, each fixture digest,
Rust version, Cargo.lock digest, and resolved upstream package/license inventory.
Registry archives are verified by Cargo against their locked checksums. The
upstream license texts remain with source packages; LICENSES contains copies
for the resolved dependency graph, organized by package and version. One
upstream package, hifijson 0.2.3, declares MIT but supplies no license text;
the inventory records that upstream packaging limitation explicitly.
